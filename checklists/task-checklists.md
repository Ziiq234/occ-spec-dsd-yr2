# Task checklists

Built from the mark scheme. Tick off before submitting each task.

## Task 1 — Analyse and design (9–19 Mar, 18 hrs)

### A — Proposal (~9 hrs)
- [ ] Business context (client, users, current situation, problem)
- [ ] Research on current practice and emerging tech in the sector, in an appendix with sources
- [ ] Functional requirements table (IDs, measurable)
- [ ] Non-functional requirements table (performance, security, accessibility, compatibility)
- [ ] Decomposition diagram/breakdown covering every requirement
- [ ] KPIs with targets
- [ ] User acceptance criteria (Given/When/Then), linked to requirements
- [ ] Solution description (platform, languages, database, architecture)
- [ ] Justification: how it meets client and user needs
- [ ] Risk table: SQL injection, XSS, man-in-the-middle, validation, data breach — with mitigation
- [ ] Legal/regulatory: GDPR/DPA 2018, Computer Misuse Act, copyright/IP, Equality Act + W3C/WCAG, PECR cookies, ISO/IEC/IEEE 90003
- [ ] Technical language for developers, plain language for client justifications

### B — Designs (~4.5 hrs)
- [ ] Style guide (colours with contrast, fonts, spacing, components, accessibility)
- [ ] Wireframes for every key screen — **desktop and mobile**
- [ ] Visual hierarchy, white space, standard conventions (nav, icons, hamburger)
- [ ] ERD with crow's foot notation and keys
- [ ] Data dictionary (types, sizes, keys, validation, input masks, examples)
- [ ] Error handling: validation rules and user error messages
- [ ] Consistent naming between ERD, dictionary and wireframes
- [ ] Could a third-party developer build it from these alone?

### C — AI log (~4.5 hrs)
- [ ] Up to 5 different problems, front end **and** back end, more than one language
- [ ] Precise prompts, refined each iteration
- [ ] Detailed review per output: positives, negatives, refinements
- [ ] Shows integration into the larger solution
- [ ] PDF with correct name

## Task 2 — Develop (22 Mar–23 Apr, 20 hrs)

### A — Prototype (~12.5 hrs)
- [ ] Front end and back end, 2+ permitted languages
- [ ] Linked multi-table database (DDL + DML)
- [ ] AI code from Task 1 used appropriately
- [ ] Classes/functions, no copy-paste, constants, minimal globals
- [ ] Clear comments and consistent naming
- [ ] Validation, sanitisation, parameterised queries, exception handling
- [ ] Helpful, jargon-free error messages
- [ ] Role-based login, hashed passwords
- [ ] Accessibility settings (font size, contrast/colours)
- [ ] Cookie notice, privacy policy, T&Cs, GDPR
- [ ] Works on target platforms (fallback code)
- [ ] Packaged build + source code + **screencast** of front end and back end

### B — Documentation (~7.5 hrs)
- [ ] Test log: unit, validation, security, load, compatibility, accessibility, black box
- [ ] Automated test setup and results screenshots
- [ ] Each failed test → fix → retest recorded
- [ ] Change log: date, summary, file + version
- [ ] Source log: all code/AI/data/assets, how used, legal/IP

## Task 3 — Feedback and evaluation (24 Apr–5 May, 12.5 hrs)

### 3a — Feedback (10 hrs)
- [ ] Separate demo/screencast for technical and non-technical audiences
- [ ] Questionnaires with open and closed questions, per audience
- [ ] Observation record (tasks, pain points)
- [ ] Paired code review record
- [ ] Feedback recorded in a format that can be analysed (tables, scores)

### 3b — Evaluation (2.5 hrs, no internet, no AI)
- [ ] Assets/content: why chosen or rejected, validity and reliability, bias, legal/ethical
- [ ] Each functional and non-functional requirement: met / partly / not met, with evidence
- [ ] Each acceptance criterion: met or not, with evidence
- [ ] Future developments justified by feedback quotes and prototype examples
- [ ] Prepare notes beforehand from Task 1 and 2 read-only copies

# How much AI can I use? — exact rules (Gen 2)

Taken word-for-word from the Gen 2 AdSAM task booklets (Feb 2026, `papers/gen2/text/`). The SAM says the same. **Confirm with college before 9 March** — the real 2027 booklets are the final word, and college decides which AI tool you'll have access to.

## At a glance

| | Task 1A Proposal | Task 1B Designs | Task 1C AI log | Task 2A Prototype | Task 2B Documentation | Task 3A Feedback | Task 3B Evaluation |
|---|---|---|---|---|---|---|---|
| **AI allowed?** | ❌ | ❌ | ✅ **required** | ⚠️ small code + test/debug only | ⚠️ only the testing itself | ❌ | ❌ |
| **Internet?** | ✅ monitored | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |

## Task 1 (18 hrs)
> "During this task you are only permitted to use AI during Activity C. You are not permitted to use AI or any other tool designed to automate producing a response for any other activity during this task."

- **Proposal and designs: no AI at all.** Not for research summaries, wording, ERDs, wireframes or spell-checking beyond a normal spell checker.
- **Activity C: you must use generative AI** to make code snippets for **max 5 problems**, not a whole solution. Log the prompts, review positives and negatives, show refinements and iteration.

## Task 2 (20 hrs)
> "you are not permitted to use AI or any other tool designed to automate producing a complete digital solution. However, you are permitted to use AI tools to:
> • generate small sections of code to solve specific problems that can be integrated into a larger solution
> • automatically test and debug code you have produced."

So in Task 2 you **can**:
- ✅ Generate **small** pieces of code for specific problems (and reuse your Task 1C snippets — the booklet says "make appropriate use of the code generated by AI in Task 1").
- ✅ **Troubleshoot/debug** — paste your error or your function and ask what's wrong. *("code you have produced" — it's for fixing your code, not writing it.)*
- ✅ Use AI to **test** — generate unit tests, test data, or review your code for bugs/security. This also earns marks: the mark scheme lists "AI-assisted testing" as testing evidence.

You **can't**:
- ❌ Ask AI to build the whole app, whole pages or whole features in one go.
- ❌ Use AI to write the test log, change log or source log text — only the testing itself is on the allowed list.

And you **must**:
- 📝 Record **every** piece of AI-generated code in the **source log** — what you asked, where it went, how you changed it, IP/legal points. Undeclared AI code is malpractice.

## Task 3 (10 hrs + 2.5 hrs)
> "During this task you are not permitted to use AI or any other tool designed to automate producing a response."

- ❌ No AI for questionnaires, screencast scripts, analysing feedback, or the evaluation.
- 3B also has **no internet**. You get read-only copies of your Task 1 and 2 work and your feedback materials.

## Practical tips for using AI well in the tasks
1. **Debug prompts:** paste the exact error + the smallest bit of code that causes it + what you expected. Ask *why* it fails, not just for a fix — you need to explain the fix in your test log.
2. **Keep snippets small:** one function or one query per prompt. If the answer is more than ~40 lines, it's probably too big.
3. **Always change and understand it:** rename to your conventions, add your validation, add comments explaining *why*. Code you can't explain is a risk.
4. **Screenshot as you go:** prompt + output, so the source log and test log are easy to fill in.
5. **Check it for security:** AI code often builds SQL with string concatenation or skips validation — catching that is exactly the kind of review that scores in 1C and in testing.

## Questions to ask college
- Which AI tool(s) will be available in sessions (ChatGPT, Copilot, Gemini, Claude…)? Practise with that one.
- Is GitHub Copilot / IDE autocomplete counted as AI? (Treat it as AI unless told otherwise — it's "designed to automate producing a response".)
- Can research notes be brought into Task 1 (Gen 1 allowed facts and figures only)?
